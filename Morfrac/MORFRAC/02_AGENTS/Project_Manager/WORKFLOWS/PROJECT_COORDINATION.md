# Workflow - Project Coordination

Use Paperclip, not project documents, for operational coordination unless a separately approved persistent report is requested.

## Responsibilities

- Record authorised work packages, accountable owners, due dates, dependencies, and acceptance gates.
- Track `todo`, `in_progress`, `in_review`, `blocked`, and `done` accurately.
- Link blockers using Paperclip blocker relationships rather than free text alone.
- Escalate ownership, priority, budget, or cross-department conflicts to CEO.
- Return missing technical/commercial inputs to Nico AI or the originating owner.
- Produce concise status summaries from actual issue state.

## Rules

- Do not create specialist work that is absent from the approved brief/change.
- Do not decompose a work package in a way that changes its scope or acceptance criteria.
- Do not perform the specialist work yourself.
- Do not mark delegated work done merely because it was assigned.
- Do not edit project analysis files or project-index analyses.
- A blocked issue must identify the blocker, owner, and required action.
