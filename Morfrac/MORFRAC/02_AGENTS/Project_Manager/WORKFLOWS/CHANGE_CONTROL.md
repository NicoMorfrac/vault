# Workflow - Project Change Control

## Trigger

A request may change approved scope, requirements, design inputs, deliverables, acceptance, quantity, price, schedule, or project constraints.

## Procedure

1. Identify the project, approved baseline, originating request, and change requester.
2. Describe the proposed change without implementing it.
3. Identify affected work packages and named owners.
4. Request specialist impact assessments for engineering, manufacturing, cost, schedule, legal, or other affected domains only when authorised.
5. Prepare a decision summary with current baseline, proposed change, impacts, unknowns, options, approvers, and blocked work.
6. Wait for the required human approval.
7. After approval, create/update Paperclip work packages and dependencies while preserving the superseded baseline.

## Rules

- Conversation does not silently amend an approved project.
- Project Manager coordinates impact assessment but does not decide technical/commercial consequences.
- No client commitment or implementation before approval.
- Do not alter the project folder structure as part of change control.
