# TASK PATTERNS

## Pattern 1 — Discover Engineering Authority Opportunity

### Objective

Identify a high-value authority-content opportunity derived from real engineering problems, system-level sailing challenges, or technical integration issues.

### Opportunity Sources

Examples:

* furling integration challenges
* retrofit engineering
* textile interface problems
* friction-management limitations
* load-path optimization
* rigging simplification
* installation geometry conflicts
* material-selection tradeoffs
* technical troubleshooting
* manufacturing constraints

### Required Actions

* identify the engineering problem
* explain why it matters
* identify authority-building potential
* identify commercial relevance
* identify AI retrieval value
* identify entity reinforcement opportunities
* identify semantic ecosystem opportunities

### Output

Save proposal under:

```text
06_MARKETING/SEO_Content_Proposals/
```

Example:

```text
YYYY-MM-DD_Furling_Integration_Opportunity.md
```

## Pattern 9 — Strategic Opportunity Validation

### Objective

Validate authority opportunities before save.

### Validation Checklist

Before saving proposals:

* verify engineering relevance
* verify commercial relevance
* verify semantic ecosystem coherence
* verify AI retrieval value
* verify entity reinforcement exists
* verify commercial routing exists
* verify no shallow SEO thinking
* verify no disconnected filler topics
* verify no confidential engineering exposure

### Failure Handling

If validation fails:

* revise before save
* do not save low-value authority proposals

The agent must never knowingly save weak authority opportunities.

## Pattern 11 - Obsidian Metadata Classification

### Objective

Classify every generated Markdown file before saving.

### Report Outputs

Use report metadata for authority opportunity reports, ecosystem proposal reports, strategic content opportunity reports, and validation reports.

Report outputs must comply with [[00_SYSTEM/OBSIDIAN_REPORT_STANDARD.md]]:

```yaml
---
type:
source_agent: Technical_Content_Strategy
created:
related_findings: []
related_concepts: []
related_projects: []
related_reports: []
---
```

Report outputs must include:

```markdown
## Related Links
```

### Content Assets

Use content-asset metadata for draft outlines, externally oriented content plans, derivative content outlines, and reusable marketing content assets:

```yaml
---
type: content_asset
source_agent: Technical_Content_Strategy
created:
related_projects: []
related_topics: []
---
```

Do not force Business Intel report metadata into marketing or content assets.

Do not auto-link generic words such as engineering, retrofit, hardware, serviceability, analysis, marketing, SEO, or project.
