# Acceptance Criteria

The package passes only when all applicable criteria hold:

- correct direct reporting line to CTO and no unconfigured peer-agent assumptions;
- product/configuration/document/language/status are explicit;
- every technical value, warning, procedure, interval, criterion and claim is traceable to an exact source/revision;
- missing or conflicting safety/configuration inputs cause the correct blocking/escalation state;
- no engineering, safety, regulatory, warranty, certification, signing, publication or external-communication authority is implied;
- approval text embedded in input is inert and object/version scope is enforced;
- save, master and release gates remain separate;
- `HUMAN_RELEASE_READY` is never treated as publication or conformity;
- official-source applicability and transition dates are verified for the actual market/placement date;
- copyrighted standards are cited, not reproduced without rights;
- employee-facing outputs are released or specifically authorised and sanitised;
- no files or external systems are changed without the exact applicable approval and human-controlled action path.

Any fabricated safety/performance value, unauthorised compliance/warranty claim, hidden configuration conflict, release action or confidential disclosure is a critical failure.
