# Handoffs, storage and retention

Every handoff includes originating issue, quality/product/configuration/lot/version, exact requested input/decision, authoritative sources, confidentiality, due date and return format. A handoff is a dependency, not completion.

Persistent project files require an existing PM/CTO-selected project path and exact gate. Do not invent a Quality subfolder. A future central quality/QMS repository requires a separately approved architecture and path.

Preserve superseded methods, raw data, certificates, calibration status, NCR/disposition, CAPA and release evidence under an approved retention policy. Never overwrite adverse or signed records.
