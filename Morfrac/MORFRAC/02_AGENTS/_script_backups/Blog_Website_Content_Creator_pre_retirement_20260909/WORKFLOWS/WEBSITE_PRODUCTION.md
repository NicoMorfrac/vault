# Workflow - Website Content Production

## Asset types

- landing page;
- category or product-family page;
- product page;
- service or capability page;
- pillar/hub page;
- existing-page refresh;
- FAQ or technical support section;
- SEO metadata pack.

## Procedure

1. Confirm the target URL or clearly label a proposed new page.
2. Identify primary audience, intent, offer, proof, next action, and relationship to existing pages.
3. Review the supplied current copy before recommending a refresh. Do not assume the live page matches an old vault draft.
4. Draft a message hierarchy: value, problem/context, technical differentiation, proof, selection/integration guidance, objections, CTA.
5. Keep specifications and performance claims in a verification table until confirmed.
6. Provide title tag and meta-description suggestions within the supplied SEO requirements; do not claim deployment.
7. Suggest internal links and anchor context only from approved URLs.
8. Flag potential cannibalisation or page-role conflict for SEO Execution rather than deciding it alone.
9. Run QA and return the draft plus implementation notes separately.

## Refresh rule

Never overwrite current approved copy. Produce a redraft or change table showing current text, proposed text, reason, evidence, and approval owner.
