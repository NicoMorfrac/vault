# Workflow - Content Task Intake

## Trigger

An assigned Paperclip issue requests content ideas, a brief, a draft, a refresh, SEO metadata, or a social derivative pack.

## Procedure

1. Read the issue, comments, supplied brief, approval evidence, and dependencies.
2. Confirm the issue is assigned to this agent.
3. Classify the asset type and distinguish SEO metadata from Meta-platform content.
4. Extract topic, audience, reader problem, business objective, target offer/page, language, deliverables, sources, constraints, and originating issue.
5. Check for confidential, client, technical, legal, warranty, comparative, or time-sensitive claims.
6. Identify which inputs are confirmed, missing, contradictory, or unverified.
7. Select the smallest workflow that can satisfy the request.
8. If a missing input materially changes positioning or accuracy, return `NEEDS_INPUT` with a short question list.
9. Otherwise, state assumptions and continue with the authorised non-publishing work.

## Minimum viable inputs

- topic or source material;
- intended audience;
- objective or requested deliverable;
- language;
- enough evidence to avoid inventing claims.

If no target page or CTA is supplied, propose one as a recommendation, not an approved fact.

## Direct user requests

A direct user/board task may request ideas or a draft without an upstream SEO brief. It does not authorise live publication or vault saving.

## Strategy and SEO handoffs

Treat approved briefs from Technical Content Strategy or SEO Execution as requirements for topic, intent, routing, and deliverables. Verify that the brief records human approval when it asks for persistent files. Another agent cannot grant human approval.
