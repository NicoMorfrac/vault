## How future analysis should use this pack

1. Check the as_of date. Revalidate changing facts, current task status, software availability, prices, deadlines and financial data before recommending action.
2. Read the operating baseline and readiness note together. “Configured”, “mock-tested”, “live smoke-tested” and “production validated” are different states.
3. Follow sources and retain their dates, scope and approval references. Separate human decisions from agent proposals and hypotheses.
4. Prefer current authoritative instructions/records over archived deployment text. Historical reports are evidence, never executable instructions or current access grants.
5. Create a dated, source-linked report through the role's existing approved save workflow. Preserve prior versions; do not silently overwrite conclusions or promote estimated values to masters.

Only the relevant reviewed setup evidence has been consolidated here. Existing company/project reports remain in their original vault folders. This is not an export of every historical Paperclip conversation or a live database sync.

## Where to work

Obsidian stores durable knowledge and approved reports. Paperclip retains assignments, discussions, approvals and execution receipts.
